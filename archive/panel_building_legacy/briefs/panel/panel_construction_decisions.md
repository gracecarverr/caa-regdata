# Asset & Panel Construction Decisions

> ⚠ **Code cross-references predate the current layout.** The *decisions and data facts below remain valid*,
> but some cited paths/filenames (e.g. `assets/facilities.R`, `presets/…`, `build_panel(years=)`,
> `00_setup.R:8`, `data/clean/…`) come from an earlier architecture. The current pipeline lives under
> `code/` with standalone panel scripts in `code/03_panel_building/04_panels/` and cleaned assets in
> `data/processed/`. Being reconciled during line-by-line verification — confirm exact locations in the
> current `code/` tree. See `briefs/institutional_overview.md` for the institutional hub.

> 📌 **REVISION 2026-07-17 — panel counts are no longer deduped (supersedes P2 core/raw semantics, and the
> penalty `dup==0` in E4).** Every panel `n_*` now counts **all rows** (no `dup==0` filter). Duplicate load
> is surfaced, never removed, by two indicators per duplicated family — `n_*_dup` (event-key repeats, `dup>0`)
> and `n_*_dup_exact` (byte-identical, `dup_exact==1`) — for **inspections**, **enforcement** (+ `n_formal_dup`
> / `n_informal_dup`), and **certs**; `violations`/`stacktests` carry zero dups (asserted in the build).
> Recover the old event-distinct count as `n_x − n_x_dup`. The old all-row twins `n_certs_raw` /
> `n_enforcement_raw` are **removed** (now equal to the headline count). **Penalty:** `penalty_amount` now
> sums **all** formal rows; a new `penalty_amount_dup` reports the dollars from event-key duplicate rows.
> **Exception:** the interval HPV flag `hpv_active` (P8) keeps `dup==0` — it is a status flag, not a count,
> and duplicate spell rows carry the same interval (output-identical). **Measured duplicate load** (Σ`dup`/Σ`count`
> over observed facility-years, `output/panel_profile/summary_duplication.csv`) is near-identical across panels:
> certs **~81%**, informal enforcement **~48%**, pooled enforcement **~34–36%**, formal **~1%**, inspections
> **~0%** (violations/stacktests 0). Duplicate **penalty dollars** are **4.6%** of the universe total
> (**$205.9M** of **$4.485B**, as of 2026-07-27 — was $206.0M/$4.483B), 4.9% major/synmin, 11.6% electric
> (`summary_penalty.csv`: `dup_total`/`dup_share`).
> These dollars come from very few rows — **238** duplicate penalty rows (formal `dup>0` with penalty>0) in
> universe (was 284), **207** major/synmin (was 246), **20** electric (unchanged; ~0.55% of penalty-bearing
> formal rows) — but high-value ones (electric's 20 rows ≈ $2.6M each), so the dollar share dwarfs the row
> share. All are re-entries under the same `ENF_IDENTIFIER`, **none byte-identical** (`dup_exact=0` for formal).
> The **asset layer is unchanged** —
> CC9 still keeps every raw row flagged; only the panel aggregation stopped deduping. *Why:* counts should be
> honest about the raw record and make duplication measurable in-place rather than silently dropping it. The
> P2 / "Core counts" / "Raw counts" / W6 / E4 wording below describes the pre-revision behavior.

Of 122,847 active facilities with a pollutant record, 16,868 have *only* the aggregate signal (would have been silently misclassified non-HAP-emitting if the old rule were dropped instead of kept), and 13,177 have *only* a named-HAP/CAS match (the coverage gap the old rule had) — 13,710 have both. Net: active-universe `emits_hap=1` facility count rose from 30,578 (old rule alone, within this population) to **43,755** (union) — spine-wide, 43,755 of 133,753 facilities (32.7%). A coverage diagnostic (`pollutants coverage: N / M rows (%) match none of the six emits_* categories`) is now printed on every spine build so any residual gap stays visible rather than silent. **Addendum (2026-07-28) — `emits_voc` false positive fixed:** `grepl("VOLATILE ORGANIC", POLLUTANT_DESC)` also matched `POLLUTANT_CODE 300000310` "NON-VOLATILE ORGANIC COMPOUNDS" — the opposite category, a plain substring match with no negation handling (found via `code/04_datasets/01_regulatory.R`'s parallel audit, same day; 49 facilities/54 rows carried that code, 30 facilities had no other genuine VOC-matching row to fall back on and flipped from `emits_voc=1` to the correct `0`). Ported into this file from the dataset layer's identical fix. |

### B.7 `wayback` historical status — sources `ICIS_AIR_WAYBACK/ICIS-AIR_downloads_{2015..2025}`
Reconstructs **year-varying** facility operating status + program-active flags from the **11 annual ICIS-AIR snapshots** (echo.epa.gov downloads captured Sep–Nov each year, 2015–2025). Built in `code/02_cleaning/wayback/{17,18,19}_wayback_*.R`; the live download gives only one current snapshot. Three clean assets: `wayback_facility_status.csv.gz` (facility×year), `wayback_facility_spells.csv.gz` (facility summary → spine F7), `wayback_program_status.csv.gz` (facility×year, 10 program groups).

## Part D · Data issues & nuances the pipeline touches

**Handled in the assets (no action needed downstream):**
- Row-grain double-counting `[B1]` → all rows kept + `dup` flag; canonical counts use `dup==0` (CC9). Two-format dates `[C7]` → `mdy` (CC3). Multi-facility penalty broadcast `[F2]` → sum penalties over `dup==0` (E4). Out-of-range/undated events `[C4,C5]` → dropped (CC4).

**Carried as documented caveats (the analyst must remember):**
- Snapshot class/industry/operating status applied to all years `[A1, A2, A5]` (F2, P1). No facility entry/exit → ambiguous zeros `[A3]` (P3, P4). Violation date-rule choice moves counts `[C1]` (V1). Early-year violation sparsity is an artifact `[C2]` (V5). Formal-action settlement-date lag `[C3]` (E2). Cert under-coverage of majors `[F4]` (T3). Right-truncation of 2025 `[C6]` (CC2). HPV status inherits the early-year violation-coverage ramp (P8/V5); program enrollment is ever-enrolled and static (F6, N7).

**Nuances worth knowing (subtle, not in the matrix):**
- **N1 — no rows are dropped (CC9); `dup==0` marks the first row of each event id.** When an event id spans several raw rows (e.g. a violation across multiple `program`/`pollutant` values, or a cert's ~5 program/pollutant rows), every row is retained; `dup==0` is the first (its descriptive columns match the old asset), `dup>0` the rest, and `dup_exact` says whether a repeat is byte-identical or carries new sub-detail. Event-level work filters `dup==0`; the multi-valued detail that the old dedup discarded is now recoverable from the `dup>0` rows.
- **N2 — the spine's active-window is hard-coded to `YEARS` (2005–2025)** in `facilities.R`, independent of `build_panel(years=)`. Building a panel for a *wider* window would still only see facilities active in 2005–2025; widen both if needed.
- **N3 — "first non-blank" ≠ "first parseable"** (`first_nonblank`): a non-blank-but-malformed `FRV` date would be taken and the good `HPV` fallback skipped. Currently 0 unparseable, so no effect — a latent fragility (open-questions D-B5).
- **N4 — unplaceable facilities cascade:** no FRS coordinate → no `county_fips` (F4). Coordinate coverage is the gate for all geography-based joins.
- **N5 — FRS coordinate & facility-attribute dedup keep the first record** (`distinct(REGISTRY_ID)`, `distinct(PGM_SYS_ID)`); a site with multiple coordinate records or a facility with multiple attribute rows silently takes the first.
- **N6 — HPV status ≠ HPV count, and open-spell handling is conservative.** `hpv_active`/`hpv_active_1mo` (interval, ongoing status) and `n_hpv` (recorded-year count) answer different questions and will not agree year-to-year (P8). Open spells (no resolution) and `resolved < dayzero` rows are treated **day-zero-year-only**, so an unresolved HPV contributes status to *one* year only — deliberately understating rather than fabricating multi-year status. The two `hpv_resolved_date`/`hpv_dayzero_date` junk dates (3-digit years) fail to parse and fall through the same NA-guards (dropped / treated as open).
- **N7 — `prog_*`/`n_programs = 0` means "no enrollment record," not "confirmed not enrolled."** Missing PROGRAMS rows coalesce to `0` (like `emits_*`); 3,236 active facilities have no record at all. And because these are **ever-enrolled** flags with no end date, they cannot date *when* a facility came under a program — use with care in any timing/event-study design (F6).
- **N8 — `exit_source == "dropout"` cannot be adjudicated by regulatory events, and is ~disjoint from the event universe.** Of **30,774** observed exits (14% of ever-operating facilities), **18,802** are `cls` (an observed Permanently-Closed status), **171** `other`, and **11,801** `dropout` (last seen operating, then vanished — kept distinct from `cls` because a disappearance can be an ICIS *extract artifact* rather than a real closure, F7). The obvious test for artifact-vs-closure — does the facility generate regulatory activity *after* its vanish year? — is a **dead end here**: only **1 of the 11,801** dropouts appears in *any* of the six event assets at all (vs 51% of all wayback facilities). This is structural, not noise — facilities with regulatory activity persist in the ICIS facility extract, so the ones that vanish are precisely the event-less. The lone exception (`03000PA00011`, `exited_year` 2019) does carry an event dated **2026**, seven years post-vanish — a confirmed extract artifact, not a closure — which both proves the mechanism exists *and* shows how rarely events can catch it. Treat `cls` (18,802) as trustworthy exits; `dropout` (11,801) as well? Independent activity channels that *could* help with identifying status: programs `UPDATED_DATE`, year-stamped `POLL_RPT_COMBINED_EMISSIONS`.
- **N9 — the spell summary assumes a single continuous operating episode; genuine reopenings (0.26%) are collapsed there but preserved in the panel.** `entered_year` = *first* operating year, `last_op_year`/`exited_year` = *last* operating year (18_), with no check for interruptions in between — so a facility that operates, closes, then reopens is summarized as one spell `[entered, exited]`. This is deliberate (**reopening-robust**: defining exit off the *last* operating year stops a mid-window closure from fabricating a spurious early exit, F7), but the same choice **erases the intermediate closure** from the one-row summary. Empirically rare (`output/panel_deep_stats/n9_reopen_detection.csv`, `06b_panel_deep_stats.R`): **583 of 220,579** ever-operating facilities (**0.26%**) have ≥1 genuine non-operating year strictly inside their span — real transitions (**1,353** interrupting facility-years are `CLS`, 126 `CNS`, 46 `PLN`), i.e. "Permanently Closed" is not always permanent in ICIS. **Scope of the loss:** only the spine spell fields (`entered_year`/`exited_year`/`exit_source`, F7) collapse; the **year-varying** `operating`/`op_status_code` in the panel (W-block, B.7) retains the true per-year sequence (a close→reopen still reads `1,0,…,1`). So year-by-year work is unaffected; only treating `[entered_year, exited_year]` as a *continuous* in-service interval mis-covers these 583. `exit_source` is likewise classified on the **final** transition only, so a `CLS`→reopen→vanish facility is typed by its last event, not its first closure. **Effect by panel** (strict operating→`CLS`→operating sequence in the 2015–2025 snapshots, wayback-side counts stable — 583 total reopen facilities unchanged): as of 2026-07-27, **418 of 132,461** reach the `universe` panel (0.32%, was 373 of 135,213 / 0.28%), **241 of 45,212** `major_synmin` (0.53%, was 211/45,423 / 0.46%), **26 of 3,015** `electric` (0.86%, was 21/3,025 / 0.69%) — nested subsets, share rising with source size (bigger sources reopen more); the rest are non-CONUS or not ever-active in-window. The per-panel counts moved more than the total-reopen-facility count (fixed at 583) because the shrinking/reshuffled ICIS roster changed which facilities fall in each subset, not because reopening itself changed. Immaterial everywhere (<1%), and only the spine spell fields collapse them — the panel's year-varying `operating`/`op_status_code` keeps each reopen as `1,…,0,…,1`. **Interior closed years are `NA`, not `0`** (W6): of the **998** `CLS` facility-years among universe reopen facilities (last profiled figure, not independently re-verified this pass), **729 (73%)** are `obs_source=="unobserved"` → all counts `NA`; the other **269 (27%)** became observed only because a regulatory event landed that year (`obs_source=="event"`). `CLS` never triggers the operating known-zero fill (that needs `operating==1` = `OPR/TMP/SEA`) — so a closed year is a real zero only when an event independently observes it, never by assumption.
- **N10 — year-varying `prog_*_active` reads "absence of a program record as a 0," which is record-backed 97.8% of the time and a forced zero 2.18%** (⚠ this entire note's figures are from the original 2026-07-18 measurement and were **not independently re-derived in the 2026-07-27 refresh pass** — re-deriving them requires access to `19_wayback_program_status.R`'s intermediate "present" flag, not just its final 0/1/NA output columns, so this is flagged rather than guessed at). `19_wayback_program_status.R` reconstructs `prog_{sip,titlev,…}_active` per snapshot year from **snapshot presence**, not `BEGIN_DATE` (ignored, unreliable): a facility **present** in the year's `ICIS-AIR_FACILITIES` snapshot but carrying no active row for group X (active per the N11 program-specific rule) is coded `0`, not `NA` (the structural-zero convention, gated on facility presence). This rests on ICIS-AIR PROGRAMS listing *all* active assignments each year. Empirically (as last measured): of **2,811,232** present facility-years, **97.82%** have ≥1 PROGRAMS row, so an absent group there is a genuine "in the table, not in this program" zero; but **2.18% (61,397)** are present with **zero PROGRAMS rows at all** — for these every one of the 8 flags is forced to `0` with no record backing any of them, and `0` there could equally mean "extract missing this facility-year" rather than "confirmed not enrolled." Distinct from the **static** spine flags (N7, F6): those are ever-enrolled/undated; these are year-resolved but inherit the same missing→`0` risk in the no-record cohort. The subsequent **LOCF** (interior-gap carry-forward, mirroring `17_`) is negligible in magnitude — **75** facility-years across **32** facilities (0.003%) — so the "coverage unchanged until evidence otherwise" step is not the binding assumption; the no-record forced zero is. **Addendum (2026-07-27):** "every one of the 8 flags" is stale — the schema now carries 10 groups (`prog_gact_active`/`prog_cfc_active` included), same forced-zero logic applies to both; see `docs/data_dictionary_derived.md` Part 2.
- **N11 — `prog_*_active` uses a PROGRAM-SPECIFIC active rule (revised 2026-07-18; was a blacklist).** `19_` now keeps a program row as active via a group-aware filter: `AIR_OPERATING_STATUS_CODE %in% c("OPR","TMP","SEA")` for the six **operating** programs (`sip/titlev/nsps/mact/neshap/fesop`), **or** `AIR_OPERATING_STATUS_CODE %in% c("PLN","CNS")` additionally for the two **preconstruction** programs **NSR & PSD** — those permits attach *before* a source operates, so planned / under-construction years are genuinely subject to them. `CLS`, the rare `NER/NED/NES/LDF`, and a missing status are inactive for every group. **Why not a plain whitelist:** mirroring the `17_` operating whitelist (`OPR/TMP/SEA`) everywhere would wrongly zero `prog_nsr_active`/`prog_psd_active` exactly during construction, when those permits bind; the old blacklist (active unless `CLS`) over-counted the operating programs by treating `PLN/CNS` as active. **Effect of the switch** (facility-year flags flipped `1→0` vs the blacklist, no `0→1`): sip 14,987, mact 7,344, nsps 6,650, titlev 2,692, neshap 2,210, fesop 549 (all lose `PLN/CNS/NER/…`); nsr 29, psd 5 (lose only `NER/NED/NES/LDF`, keep `PLN/CNS`). The **NA-status branch is vacuous** — 0 of 4,310,008 in-group rows have a missing code — so "missing → inactive" changes nothing today. **Still deliberately diverges from `operating`:** an `NSR`/`PSD` facility in `PLN`/`CNS` reads `operating = 0` but `prog_nsr_active = 1` (subject-to, not operating-under); the six operating flags now agree with `operating` on `PLN/CNS`. Resolves open-questions **D-C5**.
- **N12 — Major emissions Title V cert coverage** (measured 2026-07-18, refreshed 2026-07-27). Of operating **Major Emissions** facilities (by `AIR_POLLUTANT_CLASS_DESC`), **72.7%** have a reported cert in 2025 (9,456 of 12,998; was 72.5%/9,428 of 13,012), down from 77.6% in 2015 (9,666 of 12,461; was 77.5%) — a **3,542-facility gap** (was 3,584). Spot-check reveals the issue: 2025 certs are sparsely reported in ICIS; same facilities have historical certs (ending 2005–2024), so the absence is a **reporting lag**, not a data-quality error. Title V requires annual certs for majors. **Practical:** `any_certs` is a more reliable compliance flag than assuming `n_certs > 0` per major per year; the 2025 shortfall reflects ICIS data currency, not non-compliance.

- **N14 — `n_penalties` / `n_penalties_dup`: a count companion to `penalty_amount`** (added 2026-07-20). Per facility-year, `n_penalties` = number of **formal-action rows carrying a positive `$` penalty** (`parse_number(PENALTY_AMOUNT) > 0`), and `n_penalties_dup` = how many of those are event-key duplicates (`dup>0`) — the count analogue of `penalty_amount` / `penalty_amount_dup` (dollars). **Why:** `penalty_amount` alone can't distinguish one large penalty from several small ones in a year; the count separates frequency from magnitude. Distinct from the pre-existing **`n_penalty_action`** (an exact `ENF_TYPE_DESC == "CAA 113D1 Action For Penalty"` match) — penalties also attach to Administrative Orders, Civil Judicial Actions, etc., so `n_penalties` (any formal row with penalty $>0$) ≥ `n_penalty_action` in general. **Where built:** computed inside `agg_enforcement` (not `attach_penalty`), reading `PENALTY_AMOUNT` for **formal only** (informal has no such column; `penalty` set `NA` there). Placing it in the counts block — not the post-hoc penalty join — is deliberate: it makes `n_penalties` a genuine **`COUNT_COL`** that inherits **known-zero coding** (observed facility-year with no penalty → `0`, unobserved → `NA`; W6), honoring 0≠NA like every other `n_*`. **This intentionally diverges from `penalty_amount`, which stays `NA`-when-none** — so an observed facility-year with a formal action but no penalty dollars reads `n_penalties = 0` **and** `penalty_amount = NA`. **All-row basis (no dedup)** matches `penalty_amount`; recover event-distinct penalties as `n_penalties − n_penalties_dup`. **Verified** (2026-07-20, sample of 3,000 penalty-bearing facilities): `agg_enforcement` counts match an independent raw recount from `formal_actions.csv.gz` exactly (0 mismatches on both columns); and in a full `build_panel` slice the invariants hold with 0 violations — `n_penalties > 0` ⇔ `penalty_amount > 0`, `n_penalties ≤ n_formal`, `n_penalties_dup ≤ n_penalties`, observed rows never `NA`, unobserved rows always `NA`. Panel-wide totals refresh on the next full `03_build.R` run + `06_panel_profile.R` (the profile auto-discovers `n_*`, so coverage/duplication tables pick these up with no edit). Added to `PANEL_COLS` and `COUNT_COLS` (positions 40–41, in the enforcement family).

- **N13 — `coord_gross_error`/`coord_county_dist_km` flag facilities whose coordinate falls outside their ICIS-listed county** (coordinate-quality QC, complements N4). Built in the spine (`00_spine.R` via `coord_county_flag.R`): resolve ICIS `(STATE, COUNTY_NAME)` → county GEOID against the **same** `us_counties.shp` that assigns `county_fips` (so the two sides share a vintage), then measure geodesic km from the coordinate to the ICIS-claimed county polygon (computed directly on unprojected WGS84 coordinates via `sf`'s s2 backend — see the **Addendum (2026-07-28)** below on why this replaced an earlier EPSG:5070 reprojection). `coord_county_dist_km` = `0` when the coordinate lands in the claimed county, positive for a mismatch, `NA` when uncheckable. `coord_gross_error` = `1` if `dist_km > 5` (a gross error), `0` if `≤ 5` (match or near-border), **`NA` if uncheckable** — honoring 0≠NA: a facility with no coordinate, or an ICIS county name we can't resolve, never reads as `0`. As of 2026-07-27 (`output/panel_deep_stats/n13_coord_check.csv`, `06b_panel_deep_stats.R`), of **133,753** facilities (was 136,505): **1,699** gross (`1`, unchanged), **112,947** clean (`0`, was 115,007), **19,107** `NA` (was 19,799: 14,294 no coordinate + 4,813 county name unresolvable, was 15,730 + 4,069). The gross-error count held exactly steady while the clean/NA split shifted with the shrinking ever-active universe — consistent with the same root cause as everywhere else in this refresh (the 2026-07-26 ICIS-AIR snapshot). The Connecticut/`Undetermined` breakdown of the unresolvable set and the exact max mismatch distance were not independently re-verified this pass. The **5 km** cutoff excludes near-border cases (mismatch distances are median ~5 km — a facility near a county line whose coordinate sits just across). Flag is **facility-level / time-invariant** (identical across a facility's 21 rows). Full analysis + severity distribution: `code/diagnostics/coord_county_check/`. Threshold `coord_county_dist_km` directly to re-choose the cutoff without a rebuild.

**Addendum (2026-07-28) — `coord_county_dist_km` switched from EPSG:5070 to a direct geodesic distance:** the 2026-07-27 fix above made AK/HI/PR/VI/GU/MP checkable for the first time, but the distance computation still reprojected into EPSG:5070 (NAD83 / Conus Albers) — a projection only valid for the contiguous US. Checked: of 1,292 facilities in AK/HI/territories, 732 are checkable and 26 flag `coord_gross_error==1` — i.e. actively going through that CONUS-specific projection. Compared against a direct geodesic distance (`st_distance` on unprojected WGS84 coordinates, using `sf`'s s2 backend, active in this environment — no reprojection needed at all): for **3,379 CONUS mismatches** the two methods differ negligibly (mean 0.11 km, max 13 km — EPSG:5070 was fine there). For **Alaska mismatches**, the divergence was real and substantial — e.g. one read 817 km under EPSG:5070 vs 993 km geodesic (21% off), another 686 km vs 814 km (19% off). The binary `coord_gross_error` call likely never flipped (every non-CONUS mismatch found was tens-to-hundreds of km past the 5 km cutoff either way), but `coord_county_dist_km` itself was not a trustworthy distance outside CONUS. Fixed in both copies of the helper (`code/03_panel_building/coord_county_flag.R` and `code/04_datasets/coord_county_flag.R`, kept in sync per that file's own duplication warning).

- **N15 — the Major / Synthetic Minor split is confounded with STATE classification practice** (measured 2026-07-20, not independently re-verified in the 2026-07-27 refresh pass — figures below may have drifted slightly with the live ICIS-AIR snapshot but the qualitative finding is structural, not data-vintage-dependent, `major_synmin` under the operating filter, 2015–2025: 382,262 facility-years / 40,324 facilities). The synthetic-minor share of operating facilities ranges from **3.7% (TX: 2,162 Major vs 84 SynMin)** to **94.9% (VT)**, against a national **63%** — a spread far too wide to be industrial composition. Neighbouring and industrially-similar states sit on opposite ends (TX 3.7% vs OK 89.6%; LA 17.3% vs AR 76.7%), and the pattern is visible directly in the point map: Texas is near-empty of synthetic minors while its Major coverage looks normal. Synthetic-minor status is a **state-issued permit limit** (a source accepting enforceable caps to stay under major thresholds), so states differ in whether they use the device at all and whether they report it to ICIS as `AIR_POLLUTANT_CLASS_DESC`. **Practical:** any Major-vs-SynMin contrast pooled across states is partly a contrast across state regimes, not across facility size or emissions — the class variable is **not comparable across states**. State fixed effects absorb the level difference but not a class×state interaction; treating class as a facility-size proxy is unsafe without within-state comparison. **Surfaced, not corrected.** Figure + per-state table: `output/figures/majsyn_operating/class_composition_by_state.png`, `output/majsyn_operating/class_composition_by_state.csv`.
- **N16 — inside the operating filter, `obs_source` is a deterministic function of the counts, NOT an independent observation channel — do not condition on it** (measured 2026-07-20, not independently re-verified in the 2026-07-27 refresh pass — this is a structural/definitional claim, not expected to be sensitive to the live snapshot, `major_synmin` under the operating filter, 2015–2025). **Verified exactly:** the partition has no off-diagonal — all **225,837** `obs_source=="event"` rows have ≥1 nonzero count and all **156,425** `obs_source=="operating"` rows have every count `0`. So within this sample `obs_source=="event"` ⟺ `n_inspections + n_violations + n_enforcement + n_certs + n_stack_tests > 0`: it is the **extensive margin of the outcome**, not a measure of whether the facility was watched. (Outside the operating filter `obs_source` *does* carry information — it separates `unobserved` from real zeros, which is the W6 point. The collapse to a pure outcome function is specific to having already conditioned on `operating==1`.) **Consequence — the trap this note exists to prevent:** the raw class gap (**84%** of Major operating facility-years event-bearing vs **44%** of SynMin) is *not* evidence that the two classes are differently observed; it restates that majors have more recorded activity. **Conditioning on `obs_source`, or restricting to event-observed facility-years, is conditioning on a function of the outcome** — it selects on `y > 0` and will bias a class coefficient rather than clean it. **What the gap is actually made of:** mostly **Title V certifications**. Among event-years, **91.0%** of Major carry a cert vs **12.9%** of SynMin — tracking Title V enrollment (91.6% vs 3.3%, F6) almost exactly; excluding certs from the definition collapses the gap from 40 points to 27 (Major 69.0%, SynMin 41.8%). Majors file annual certs and synthetic minors are not in the program — a permit-program fact (F6/T3/N12), not a measurement asymmetry. **What genuinely differs is activity COMPOSITION** (a statement about outcomes, legitimate to report): among event-years, Major fires on certs **91.0%** / inspections **70.7%** / stack tests **29.4%** / enforcement **15.4%** / violations **12.2%**; SynMin on inspections **82.6%** / stack tests **18.1%** / certs **12.9%** / enforcement **12.9%** / violations **10.4%** — majors are cert-and-inspection driven, synthetic minors almost purely inspection-driven. **Practical:** model the counts directly (the zeros are real under W6 and must be kept); if the extensive margin is of interest, model it *as* an outcome (hurdle/two-part), never as a conditioning set. Figure: `output/figures/majsyn_operating/obs_source_composition.png` — the plotted quantity is the extensive margin, and should be read as such.

- **N17 — `HPV_RESOLVED_DATE` is populated on ~half of FRV rows that never had an `HPV_DAYZERO_DATE`** (measured 2026-07-20, `data/processed/violations.csv.gz`, all years). `ENF_RESPONSE_POLICY_CODE` (the authoritative FRV/HPV label, 56,657 FRV / 44,490 HPV) agrees with the `HPV_DAYZERO_DATE`-non-blank proxy almost exactly — **0** of the 56,657 `FRV`-coded rows carry a day-zero date (33 `HPV`-coded rows don't, negligible) — so **V2** stands.
